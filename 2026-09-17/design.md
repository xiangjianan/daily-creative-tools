# 齐件：设计说明

## 一句话巧思

让文件自己给应交清单打勾：清单准备好后，一次拖入整批文件，把漏项、多个候选和清单外文件变成一张可复制的小票。

## 用户与具体瞬间

设计师或运营准备向同事/客户发送“项目方案、报价单、品牌素材、使用说明”。文件夹里却同时有 v1、v2 和内部笔记，用户需要逐个看名、对照承诺、数是否齐全。最值得帮助的是点击发送前那几十秒，而不是再造一个项目管理系统。

## 步骤压缩与即时价值

用户先写每行一个应交关键词；之后每批文件只需拖入或多选一次，无需把文件名抄进第二栏、写公式或点击比较。立即看到缺哪项、哪项要选一份、哪些可能多带；复制的核对小票可贴到交付备注。惊喜在于一包文件会“反向暴露”清单上的空位，而不是仅展示文件本身。

## 明确规则

- Unicode NFKC、英文不区分大小写；去除首尾空白，支持常见编号/项目符号。
- 文件名包含完整关键词才算候选；不模糊猜测近义词、内容或版本。每项至少两个字符。
- 0 候选 = 缺一份；多候选 = 需选一份；单候选被多项占用 = 匹配重叠；独占但 0 B = 空文件；其余 = 已对应。
- 只有所有项独占匹配非空文件且没有清单外文件，才显示“文件名都对上了”，不显示“可以放心发送”。
- 文件列表允许移除；继续选择/拖入会追加，重复选择同文件保留歧义。真实文件首次进入替换示例；页面和复制小票标注示例。
- 一次上限 60 项 / 200 文件 / 12,000 字。超限明确报错，不截断后给出错误的完整性结论。

## 关键取舍

只处理元数据 name、size，不读取文件正文，不解压、不预览、不自动选最新版本、不重命名实际文件，也不接管邮件附件。没有账号、后台、依赖、分析埋点或浏览器持久化；CSP 禁止网络连接。清单存于当前页面内存，刷新后清空。

关键词需用户准备，这是避免不可靠自然语言推测的代价。“报价单.pdf”匹配要求该片段连续，因此不会匹配“报价单_v2.pdf”；想忽略版本应填“报价单”，想指定某份可填更完整文件名。界面举例说明了规则。

## 交互与视觉

左侧清单与文件，右侧核对小票；米白纸面、深绿“已对应”、暖色“待确认”，同时提供文字状态，颜色不是唯一提示。移动端改为单列，原生文件选择作为拖入的等价入口。文件名使用文本节点，长名可换行，避免恶意文件名被解析为 HTML。

## 不包含的能力

ZIP 内部文件、目录递归、文档内容正确性、不同版本内容比较、多份数量要求、移动系统文件应用真实设备适配测试。该工具不证明附件已发送或已送达。
